# 旅のしおりAI（tkb_2627）

## 製品概要
### 背景(製品開発のきっかけ、課題等）
旅行の計画は、行きたい場所・移動手段・時刻・費用・営業時間を何度も調べ直す作業になりがちです。AIに頼むと、それらしい旅程は出ますが、存在しない時刻や運賃が混ざったり、近い場所が別々の大きな予定に分かれたりして、そのままでは使えません。さらに、旅行中の予定変更や、仲間との共有も別のアプリに散らばっています。

### 製品説明（具体的な製品の説明）
条件（地域・日程・交通手段・予算・行きたい場所）を入れると、本人のClaudeが複数の旅程案を作り、プログラムが時刻・移動・営業時間を検証して、地図と対応した行程表で表示します。行程表はドラッグで並べ替え、予定の間から追加でき、エリアの中の予定（例：近江町市場の中の昼食）は1段下の階層で表示します。現地ではトイレ・避難場所を地図に重ねたガイドを使え、作った旅程はTwitter風のSNSで共有・コピーできます。

### 特長
#### 1. 推測しない旅程
不明な運賃・時刻・営業時間は「不明」「未取得」と表示し、AIにもプログラムにも作らせません。AIの出力はプログラムで検証し、近い予定は親子にまとめ、食事の連続も検出します。

#### 2. 地図と一体の編集
地図の番号と行程表の番号が対応し、ドラッグで並べ替え、予定の間の「＋」から追加できます。移動は出発と到着の2行、降車した駅も1つの地点として表示します。

#### 3. 安全な共有とSNS
旅程は共有サーバーのDBに保存し、公開範囲（公開・グループ・非公開）をサーバーで判定します。公開前の確認で自宅や秘密のメモを除き、写真の位置情報（EXIF）も削除します。いいね・フォロー・画像付き投稿に対応しています。

### 解決出来ること
* 旅程づくりの調べ直しを減らし、根拠のある時刻・移動・費用で計画できる
* 旅行中の予定変更（並べ替え・追加・削除）をその場で反映できる
* 仲間との共有とコピーを、プライバシーを守ったまま行える

### 今後の展望
* 国内の公共交通の経路データの拡充（現在はGoogle Routesで取得できない区間がある）
* トイレ・避難所の公式データとの接続（現在は架空の試験データ）
* 旅行中の再計画画面の再設計と、スマホ実機での最適化

### 注力したこと（こだわり等）
* AIの出力を信用せず、プログラムで検証し、不明な値を推測で埋めない設計
* 4人がAIエージェントと並行開発するための、契約（型）・タスクグラフ・自動テスト（2,000件以上）・レビュー運用の仕組み

## 開発技術
### 活用した技術
#### API・データ
* Claude Code（本人のPCで実行する旅程生成）
* Google Maps Platform（Places API (New)、Routes API、Maps JavaScript API）
* Wikipedia / Wikimedia Commons（観光解説と、ライセンスを確認した写真）

#### フレームワーク・ライブラリ・モジュール
* TypeScript、React 19、Vite、Fastify 5、Zod 4
* Node.js（node:sqlite）、Vitest、pdf-lib

#### デバイス
* PC・スマートフォンのブラウザ

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 旅程の検証と並べ替え（`packages/planner`）：時刻帯・営業時間・固定予定を考慮した順序調整、近い予定の親子まとめ、食事の連続検出
* 地図と対応した編集可能な行程表（`apps/web/src/screens/itinerary/`）：ドラッグ並べ替えを実ブラウザで検証
* SNSの公開範囲の判定と、画像のEXIF除去（`apps/server/src/social/`）
