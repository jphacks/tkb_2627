02　開始手順（最初だけM1が実施）

1
4人が各PCのtkb_2627を確認
cd tkb_2627 git rev-parse --show-toplevel git remote get-url origin git status --short
フォルダ名とリモート名がtkb_2627。別repoなら停止。未commitの変更を破棄しない。
2
M1だけがキットをコピー
# ZIPの展開先をtkb_2627と同じ階層に置く node ../tkb_2627_bootstrap_v5/scripts/place-kit.mjs --target . --expect-repo tkb_2627 # 差分が問題ない場合だけ node ../tkb_2627_bootstrap_v5/scripts/place-kit.mjs --target . --expect-repo tkb_2627 --apply node scripts/check-repo.mjs
既存READMEや設定の衝突時は自動上書きしません。dry-runで確認後、--apply --skip-conflictsで不足分だけ追加し、既存ファイルはM1が安全に統合します。
3
M1がClaude Codeで骨格を実装
claude
入力：「prompts/M1_START.txtとdocs/11_AGENT_DISPATCH.mdを読んで、B01から実装してください」。M1が共通型、最低限のUI・APIを作りブランチへpush、PRで統合。
4
他の3人はGitHubから取得
cd tkb_2627 git status --short git fetch origin # 現在ブランチが追跡するdefault branchなら # git pull --ff-only で安全に取り込む claude
各自「prompts/M2_START.txt」などを読む。新しいcloneやキット再配置はしない。
⚠ Gitのdefault branch名と現在ブランチはリポジトリごとに異なります。既にgit接続済みでも追跡先がない可能性があるため、Claude Codeに状況確認させ、安易にpullやresetを繰り返さないでください。

03　4人の担当

M1　基盤・SNS・統合共通DB、認証、SNS、契約、CI、merge管理
M2　UI画面、旅程地図同期、しおり、SNS画面
M3　旅行情報交通、観光、営業時間、時差、経路・費用
M4　Claude本人専用App Server、Claude JSON、旅程生成

役割は人間ごと。1人のClaude Codeセッション内で、作業フェーズ別のSubagentを選ぶ二段階の分業です。
