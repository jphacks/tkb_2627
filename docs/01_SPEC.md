# 旅行Webシステム仕様 v4

## 対象と処理
旅行先と期間の大枠は決まっているが、観光地選びと移動計画をまとめて支援してほしい利用者。初期入力は地域、日程、移動手段、現地タイムゾーン。予算・必須地点・出発帰着・予約・好みは必要に応じて入力する。未指定条件を勝手に確定しない。

同じ条件で2〜3案を目指すが、不成立の案を架空に作らない。行き先が離れすぎる場合は優先する希望と除外理由を示す。固定店舗とエリア自由散策を別の予定として扱う。実際の経路と時刻に基づき制約を検証し、数学的な最短経路保証はしない。

## 実行と保存の区別
本人用Web画面→本人用App Server→公式Claude Code→AnthropicのClaude→候補JSON→形式/経路/日時の検証→共通DBへ候補保存→画面に戻る。HTTP受付202と処理完了を区別する。ユーザーが採用すると共通サーバーで旅程を版付き保存する。
共有Web画面では旅程閲覧・手動編集・SNS・複製が可能。公開の生成要求を本人のProへ流さない。各人が自身のPCで動かす形は利用条件の確認が必要。共有URLのcapabilitiesで利用不可理由を表示し、「全ユーザーがClaude生成できる」と宣伝しない。

## 数値と日時
MoneyはamountMinor（最小通貨単位の整数）とcurrency。未取得はnull。複数通貨を無条件合算しない。換算時はレートと取得時刻を示す。日時はUTC時点とIANA timeZoneを併記。日跨ぎ・夏時間の欠落/重複時刻を検証。
交通情報は出発時刻ごとに区間取得。運賃、ホーム、営業時間の欠落をAIで補完しない。verifiedは取得時点での確認であり将来の保証ではない。

## 旅程編集と再計画
PATCHにはexpectedRevisionを要求し、別端末の更新後は409。再計画はcompletedとfixed予定を保存し、現在時刻と現在地から残りだけ生成する。候補の採用前に差分を見せる。取消・上限・timeout・不正出力・保存失敗を区別する。

## SNS
元旅程は非公開。公開プレビューで所有権と版とgroup所属を確認し、自宅住所・詳細現在地・秘密メモ・転載不可素材を除外。確認後の投稿では版と所属を再確認し、不変snapshotを保存する。元旅程の編集を勝手に投稿へ反映しない。
公開(public)は匿名閲覧可、groupは現時点の所属、privateはowner限定。APIでフィルタしてからページ分割。コピーはsnapshotから新ownerの下書きを作り、日付変更後は要再検証にする。公開解除/退会は次のGETから反映。既にダウンロード済みのコピーの回収は保証しない。

## ガイドと出力
GPSは同意後、拒否時は手入力。番号付き地図から解説・写真・出典を閲覧。トイレ・避難情報には取得日時と地域対応を表示。避難施設の指定と現在の開設状況を混同しない。
PDFは所有権を毎回検証し、利用許諾のある写真等だけを含める。Maps URL/ICSは初期実装案。自動アカウント書込みとは分ける。
