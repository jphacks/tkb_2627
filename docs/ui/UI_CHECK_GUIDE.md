# 画面（UI）の確認手順

画面を実際に操作して、「このままでよいか」を人が判断し、GitHubのIssueにコメントを残すための手順です。
初めての人でも、上から順に進めれば終わるように書いています。

---

## 1. 確認するのはどの画面か

確認の対象は、次の**7つの画面**です。
番号が「U」で始まらない **E01（しおり印刷）も対象**です。

| 番号 | 画面 | ホーム画面からの行き方 | コメントするIssue |
|---|---|---|---|
| U03 | 条件入力 | 「旅行を計画する」を押した最初の画面 | [#31](https://github.com/jphacks/tkb_2627/issues/31) |
| U04 | 地図と旅程 | 自分の旅程 →「地図」 | [#32](https://github.com/jphacks/tkb_2627/issues/32) |
| U05 | 旅行の計画（生成の進捗・候補の比較・採用） | 「旅行を計画する」→ 条件を入れて送信した後の画面 | [#33](https://github.com/jphacks/tkb_2627/issues/33) |
| U06 | 旅程の編集／旅行中（再計画） | 自分の旅程 →「編集」または「旅行中」 | [#34](https://github.com/jphacks/tkb_2627/issues/34) |
| U07 | 現在地とガイド | 自分の旅程 →「ガイド」 | [#35](https://github.com/jphacks/tkb_2627/issues/35) |
| U08 | SNS・グループ | 「SNS・グループ」 | [#36](https://github.com/jphacks/tkb_2627/issues/36) |
| E01 | しおり印刷・PDF | 自分の旅程 →「しおり印刷」 | [#37](https://github.com/jphacks/tkb_2627/issues/37) |

次の画面は**確認しなくて構いません**。
- U01（最初の試作）と U02（初回のレビュー）：確認済みです。
- ホーム画面：他の画面へ移るための入口です。

> **今どの画面を見ているかは、ブラウザで分かります。**
> 画面の左下に、黒い帯で「この画面：**U04** 地図と旅程」と出ます。
> 帯の中の「感想・指摘は Issue #32 へ」を押すと、コメントするIssueがそのまま開きます。

## 2. 確認の流れ（全体）

```
① 画面を起動する（M1が起動済みなら省略）
② ブラウザでホーム画面（http://127.0.0.1:5173/）を開く
③ ホーム画面の一番下にある「UI確認用：全画面の一覧」から、7画面を順に開いて触る
   （ログイン不要。試験データで開きます。ログインすると「自分の旅程」からも開けます）
④ 気になった点を、左下の帯のリンクから開いたIssueにコメントする
⑤ 問題がなければ「UI承認：OK」とコメントする
```

## 3. 画面を起動する

### 3-A. M1（KatTanaka）のPCで、M1がすでに起動している場合

起動の作業は不要です。ブラウザで次のURLを開いてください。

**http://127.0.0.1:5173/**

ログイン用のパスワードは、ターミナルで次のコマンドを実行すると表示されます。

```
cat ~/Work/tkb_2627/.local/ui-check/pw-demo-a
cat ~/Work/tkb_2627/.local/ui-check/pw-demo-b
```

- `demo-a`：金沢の旅程が1件入っています。
- `demo-b`：2人目のユーザーです。公開範囲の確認に使います。

### 3-B. 自分のPCで一から起動する場合

ターミナル（macOSでは「ターミナル」アプリ）で、`tkb_2627`のフォルダに移動してから実行します。

1. **必要なものを入れる**（初回だけ）
   ```
   npm ci
   ```
2. **設定ファイルを作る**（初回だけ）
   ```
   cp .env.example .env
   ```
   キーは空のままで構いません。画面は「fixture（架空の試験データ）」で動きます。地図には「地図キー未設定」と出ますが、確認には困りません。
3. **確認用のユーザーを2人作る**（初回だけ）
   `好きなパスワード`の部分は、自分で決めた文字列に置き換えてください。
   ```
   TKB_NEW_PASSWORD='好きなパスワード1' npm run user:create -- --login demo-a --name "デモA"
   TKB_NEW_PASSWORD='好きなパスワード2' npm run user:create -- --login demo-b --name "デモB"
   ```
4. **起動する**（確認のたびに実行）
   ```
   npm run start:shared
   ```
   このターミナルは開いたままにします。別のターミナルをもう1つ開いて、次を実行します。
   ```
   npm run dev:web
   ```
5. ブラウザで **http://127.0.0.1:5173/** を開きます。
6. 終わったら、両方のターミナルで `Ctrl + C` を押して止めます。

> 旅程がまだ1件もない場合は、ホーム →「旅行を計画する」で作ります。上の切り替えで「共有サーバー」を選び、最後に「採用」を押すと保存されます。
> Claudeを使う本物の生成は、規約上、M4のPCでしか動きません。それ以外のPCでは「AI生成は使えません」と表示されます。これは正常です。その場合は、M1に「デモ用の旅程を入れて」と頼んでください。

## 4. 各画面で確認すること

すべての画面で共通して見る点：
- 文字が読めるか、ボタンの意味が分かるか
- スマホの幅で崩れないか（Chromeで右クリック →「検証」→ 左上のスマホのアイコン）
- 分からない値が「0」ではなく「不明」「未定」と出ているか
- 試験データのときに「fixture」や【架空】と分かるか

| 番号 | 特に見るところ |
|---|---|
| U03 条件入力 | 入力が足りないときのエラー表示、通貨と予算、日ごとの交通手段、行きたい場所の追加・削除 |
| U04 地図と旅程 | 日ごとのタブ、時刻、旅程の行を押すと地図の印が強調されるか、出典の表示 |
| U05 計画 | 進捗の表示、取り消し、候補の比べやすさ、採用した後に地図へ移れるか |
| U06 編集・旅行中 | 予定の追加・削除・並べ替え、代替案と差分、「現在地を使う」の同意文、競合したときの表示 |
| U07 ガイド | 番号付きの地点、トイレと避難所の表示、「開設状況は自治体の発表を確認してください」 |
| U08 SNS・グループ | 投稿前の確認画面、公開範囲の選択。**demo-bでログインし直したとき、demo-aの非公開の投稿が見えないこと** |
| E01 しおり印刷 | 見た目、「ブラウザで印刷」のプレビュー、「PDFを作成」でダウンロードできるか |

## 5. コメントの書き方

左下の帯の「感想・指摘は Issue #○○ へ」を押して開いたIssueの、一番下のコメント欄に書きます。

問題がないとき：
```
UI承認：OK
```

直してほしい点があるとき：
```
UI承認：要修正
- 「〇〇」というボタンの意味が分かりにくい
- スマホ幅で、日付のタブがはみ出る
```

- 1つの画面につき、1件のコメントにまとめてください。
- スクリーンショットを貼ると伝わりやすいです。ただし、パスワードやAPIキーが写っていないか確認してから貼ってください。
- 「要修正」の内容は、M1が直してから、もう一度確認をお願いします。

## 6. 困ったとき

| 状況 | 対処 |
|---|---|
| ページが開かない | 3-Bの4（起動）が動いているか確認する。M1のPCの場合はM1に連絡する |
| 「ログインしてください」と出る | ホーム →「SNS・グループ」→「共有サーバー」に切り替えてログインする |
| 自分の旅程が空 | 3-Bの最後の注記を参照する |
| 左下の帯の番号が、この表にない | 確認の対象外の画面です。コメントは不要です |
